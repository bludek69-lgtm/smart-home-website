01 — Historie

Jak systém vznikal

Od první žárovky a flow „když přijdeš domů, rozsvítit" k autonomnímu systému, který se sám diagnostikuje a opravuje.

  1. Začátek · Homey Pro (2023)

    První kroky

    Klasické flow-based řízení. Pohyb → světlo → časovač. Funkční, ale s rostoucím počtem zařízení se logika začala duplikovat a kolidovat.

  2. Přechod · Homey Pro 2026

    Nová generace HW

    Migrace na Homey Pro 2026 přinesla výkon na dlouhodobě běžící HomeyScripty. Otevřela se cesta k centralizované logice v JavaScriptu místo lepení flows.

  3. Refaktor · Script-first

    Pravidlo „logika do skriptu, ne do flow"

    Veškerá rozhodovací logika přesunuta do sh_* skriptů. Flows zůstávají jako tenké triggery + akce. Vznikly routery (open space lighting, roleta, audio, vacuum) a request-first pipeline.

  4. Multi-signal · REUSE FIRST

    Architektonická pravidla

    Žádná akce z jednoho senzoru — vždy 2+ signály. Žádný hardcoded device name — vše přes Device Map. Žádný nový skript pokud lze rozšířit existující.

  5. Dashboardy · multi-resolution

    UI pro 3 obrazovky

    Greenfield redesign s premium dark layoutem. Tři varianty (1920×1080 notebook, 2880×1800 monitor, 1024×600 RPi kiosek) sdílející stejnou architekturu.

  6. Live · AI Brain Guardian

    Supervisor vrstva

    Skripty sh_state_validator, sh_brain_guardian a sh_release_guard tvoří meta-vrstvu, která kontroluje očekávaný stav, detekuje ghost values a blokuje nasazení rozbitých změn.

04 — Zařízení

Co všechno systém řídí

Zařízení rozdělená do funkčních kategorií. Každá kategorie má svůj router a svá pravidla.

💡

Světla

Open space + ložnice + pracovna. Multi-signal: FP2 presence + Z-Wave motion. Privacy režim (roleta nahoře = open space LED off).

🔥

Topení

FGS-214 + 4× TRV. Tři režimy (auto / manual / off), state-aware hystereze, anti-cycling, runtime-based kWh tracking.

🔊

Audio

Cast speakery + TTS pipeline s 200-char split. Sleep-respect (žádné TTS v noci), priority engine, radio router.

📡

Senzory

FP2 presence, Z-Wave motion, door/window kontakty, lux, teplota, vlhkost, PM2.5. Vše pipuje do request-first decisioningu.

📷

Kamery

Indoor + outdoor. Stream přes Homey, automatika spínání během odchodu / při alarm triggeru, nahrávání do encrypted storage.

🪟

Rolety

Lux-driven + rezim_doma + roleta_router v3. Hysterezis pro stable řízení, privacy guard pro open space.

🧠

AI / Diagnostika

Brain Guardian, state validator, expected state engine, release guard. Meta-vrstva nad celým systémem.

05 — Architektura

Script-first princip

Veškerá logika v jednom místě. Flow je trigger, skript je mozek, router je switchboard, device je výstup.

⚡
Flow
Trigger (čas, sensor, button)
📜
Script
Logika + multi-signal eval
📨
Request
Strukturovaný požadavek
🔀
Router
Priority + adresace
📦
Device
Reálná akce (light, TRV, speaker)
REUSE FIRST

Před vytvořením nové entity (skript, flow, proměnná) zkontroluj zda podobná již neexistuje. Refaktor > nový kód.

MULTI-SIGNAL

Žádné rozhodnutí z jednoho senzoru. Vždy 2+ nezávislé signály (např. FP2 presence + Z-Wave motion).

DEVICE MAP

Žádný hardcoded device name. Vše přes centrální mapu — když se zařízení přejmenuje, opraví se na jednom místě.

NO REGRESSION

Před úpravou existujícího skriptu: přečíst celý, ověřit volající, minimální change. „Už to fungovalo" = nesahat přes silnou potřebu.

06 — AI Brain

Guardian vrstva nad systémem

Smart home, který se sám kontroluje. Detekuje ghost values, ověřuje očekávaný stav, blokuje rozbité nasazení.

LIVE sh_brain_guardian_v1

Brain Guardian

Top-level supervisor. Agreguje výstupy validátoru a expected state engine, vypočítává health score (aktuálně 92/100). Při kritickém poklesu vyhlásí alarm.

LIVE sh_expected_state_engine_v1

Expected State Engine

Pro každý čas + režim spočítá co by mělo být zapnuté / vypnuté. Slouží jako reference proti reálnému stavu.

LIVE sh_state_validator_v1

State Validator

Porovnává očekávaný a reálný stav. Detekuje ghost values (proměnné, které lžou) a stuck flagy. První produkční detekce: priority_active=tts ghost.

LIVE sh_release_guard_v1

Release Guard

Před nasazením nové verze skriptu spustí canary checks (3 testovací volání). Pokud Brain Guardian score klesne, release se zablokuje a starý skript zůstává.
